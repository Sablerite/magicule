# Git Commands Reference — Magicule Setup

Everything we ran while setting up and pushing the Magicule repo, explained. Grouped by what you were trying to do.

---

## 1. Starting a brand new repo

```powershell
git init
```

Turns the current folder into a Git repository (creates a hidden `.git` folder). Run once, at the top level of your project.

```powershell
git add .
```

Stages all new/changed files in the folder — tells Git "include these in the next commit." Doesn't save anything permanently yet.

```powershell
git status
```

Shows what's staged, what's changed but unstaged, and what's untracked. **Always run this before committing** to sanity-check what's about to be saved.

```powershell
git commit -m "Initial commit"
```

Saves everything currently staged as a permanent snapshot in your repo's history. The `-m` message describes what the commit does.

---

## 2. Fixing the "nested repo" problem

This came up because `proton/` had its own `.git` folder inside it, which made Git treat it like a submodule instead of normal files.

```powershell
Test-Path proton\.git
```

(PowerShell) Checks if a `.git` folder exists inside `proton`. Returns `True`/`False`. Useful for confirming a folder is secretly its own repo.

```powershell
Remove-Item -Recurse -Force proton\.git
```

(PowerShell) Deletes just the nested `.git` folder — **not your actual files** — so `proton/` becomes normal tracked files instead of a separate repo.

## 3. Ignoring files you don't want tracked

```powershell
Add-Content .gitignore "target/"
```

(PowerShell) Appends a line to `.gitignore`. Anything matching that pattern (here, Rust's `target/` build folder) gets skipped by `git add` from then on.

```powershell
git reset
```

Unstages everything that was staged — doesn't touch or delete your files, just undoes `git add`. Useful when you staged something by mistake (like build artifacts) and want a clean slate before re-adding.

> **Rule of thumb:** anything auto-generated by a build (`target/`, `build/`, `*.exe`, `*.o`, etc.) should go in `.gitignore`, not get committed.

## 4. Checking/setting your identity

```powershell
git config user.name
git config user.email
```

Shows the name/email that will be attached to your commits. Empty output = nothing set (neither local nor global).

```powershell
git config user.name "Sablerite"
git config user.email "SableriteOfficial@gmail.com"
```

Sets your commit identity **for this repo only** (no `--global` flag). Good practice when you juggle multiple accounts, so each project stays tied to the right one.

## 5. Connecting to GitHub & pushing

First, create an **empty** repo on github.com (no README/gitignore/license — since you already have local commits, those would conflict).

```powershell
git remote add origin https://github.com/Sablerite/magicule.git
```

Links your local repo to a GitHub repo, nicknamed `origin`. This is a one-time setup per repo.

```powershell
git remote -v
```

Lists your configured remotes (and confirms the URL is correct) — shown for both fetch and push.

```powershell
git push -u origin master
```

Uploads your commits to GitHub. The `-u` flag sets up tracking, so future pushes/pulls on this branch can just be `git push` / `git pull` with no extra arguments.

## 6. Everyday commands (for next time)

Once a repo is set up and pushed, this is the normal day-to-day loop:

```powershell
git status
```

Check what's changed before doing anything else. Good habit to run constantly.

```powershell
git add .
git commit -m "describe what changed"
git push
```

Stage → commit → upload. (`git push` alone works now because of the `-u` tracking set up earlier.)

```powershell
git pull
```

Downloads and merges any changes from GitHub into your local copy. Run this before you start working if you (or someone else) pushed from elsewhere.

```powershell
git fetch
```

Downloads changes from GitHub **without** merging them into your files — lets you see what's new before deciding to pull it in. Safer than `pull` if you're not sure what changed.

```powershell
git log --oneline
```

Shows a compact history of commits — handy for finding a specific point to go back to.

```powershell
git branch
```

Lists your branches and shows which one you're currently on (marked with `*`).
